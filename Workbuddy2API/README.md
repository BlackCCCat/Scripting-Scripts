# WorkBuddy2API for Scripting

在 iPhone 的 Scripting 中直接授权 WorkBuddy / CodeBuddy 账号，查看余额、签到和成长任务，并提供本机或局域网 OpenAI 兼容 HTTP 接口。无需另行部署面板。

首次运行会显示 [更新说明](changelog.md)；阅读后不再重复弹出，文档内容更新时会再次显示。

## 使用

1. 在“账号”页添加账号，选择站点后点“登录授权”，脚本会获取授权链接并直接在 Scripting 内的 Safari 视图打开。也可以点“从钥匙串导入”，每次手动选择一条；只接收包含 UID、Access Token 和明确 WorkBuddy 标识或域名的凭据 JSON，其他记录会跳过。替换已有账号时会先确认。导入的凭据保存在本脚本的 Keychain 中，键名包含 UID 和昵称，便于其他脚本辨认；启动时会迁移当前脚本可访问的旧键名，清理失败会提示。没有刷新令牌的凭据到期后需要重新授权或再次导入。
2. 在“任务”页点底部“一键执行任务”：脚本重新读取全部账号任务，依次补领已达标奖励，推进当前支持的 `first_buddy`、`chat_5`、`Model_chat_GLM5.2`，回读进度后再补领新达标奖励。每项会记录已处理、待上游确认、失败或跳过；当前没有自动推进动作、未解锁、国际区只读的任务直接跳过。GLM-5.2 对话会发起真实模型请求，可能消耗账号额度；首只 Buddy 会同意上游领养协议。任务页自动加载并按账号显示任务状态，未领取任务按国内、国际分组；账号详情仍可单独接受或领取任务。任务列表合并桌面和小程序视图，优先保留可领奖任务；小程序请求失败会提示。任务页及账号详情只显示待处理任务，以及有可靠日期为当天的已领取任务；本机领取会记录领取时间。上游任务列表没有提供完成时间的历史已领任务不会显示。
3. 在“概览”顶部卡片右下角或“更多”页启动服务。默认只监听本机并固定使用端口 `8787`；可以在“更多”页编辑地址和端口，保存后运行中的服务会按新端口重启。自定义地址用于复制连接地址，监听范围由局域网开关控制；端口被占用时会报错，不会自动改用随机端口。
4. API 客户端的 Base URL 使用“更多”页复制的地址并加 `/v1`；接口不校验鉴权头，API Key 可任意填写或留空。局域网设备改用页面显示的手机 IP。

“概览”展示账号状态、余额、本机 API 请求观测到的模型限流和最近 24 小时本机用量；启动或从最小化恢复时会自动刷新余额。国内个人账号的今日签到状态在当天首次运行时从上游查询，之后沿用本机保存的结果；账号增删或点击签到后会重新查询，查询失败会在下次运行重试。点击顶部卡片的账号区域或左下角签到状态可为未签到账号签到；左下角蓝点表示已签到、绿点表示待签到、红点表示其他状态，右下角开关控制 HTTP API 服务，右上角可手动刷新余额。模型锁池只显示尚未解除的模型级限流，未观测到的上游限流不会出现在这里；上游未给出重置时间时显示本机重试时间。“数据”统计本机保留的请求记录，启动或恢复时自动重新读取，也可按时间区间及账号、模型、区域查看最近 200 次请求。积分消耗与缓存命中只在上游响应含对应字段时显示。“更多”可查看本机请求日志、查询并领取账号礼包，以及查看开学季活动留下的券码。补偿活动已被上游移除，页面只保留状态说明。

```sh
curl http://127.0.0.1:8787/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"cn:glm-5.2","messages":[{"role":"user","content":"你好"}],"stream":false}'
```

`GET /v1/models` 列出“更多 → 模型”中启用的模型。模型目录从上游账号自动拉取（`/v3/config` 与企业端点并集，过滤非对话模型和 auto/fast-model/balanced-model 路由项）；旧目录在首次打开模型页或请求 `/v1/models` 时自动刷新。国内账号的模型以 `cn:` 前缀、`owned_by: "Workbuddy"` 提供；国际与旧国际账号的模型以 `global:` 前缀、`owned_by: "Workbuddy AI"` 提供。客户端使用返回的完整模型 ID 请求聊天，前缀不会传给上游；目录已记录的模型只路由到实际返回该模型的账号。模型开关只控制列表展示，不验证账号的实时使用权限。`stream: true` 返回 OpenAI SSE 格式，但 Scripting 的 HTTP 响应需要一次性写出，所以事件会在上游完成后一起到达，不是实时逐块输出。上游模型、计费及任务接口可能变化，应以实际账号联调结果为准。

聊天接口按请求模型在可用账号间轮流分配；国内与国际模型各用自己的账号池。已知余额为零的账号会被跳过；上游明确报告额度耗尽或模型限流时，本次请求尝试下一个可用账号。普通 429 限流按短时冷却处理。余额刷新显示恢复后，额度耗尽的账号可再次参与轮询。轮询状态只保存在当前脚本实例中，脚本重新运行后从账号列表开头重新计数。

Scripting 的 HTTP 服务仅在脚本实例存活时工作。启动服务后会请求 `BackgroundKeeper` 后台音频保活，并显示锁屏实时活动；支持灵动岛的 iPhone 会显示服务图标和端口，展开后可查看访问范围与保活状态。实时活动沿用 WLOC 的原生布局方式：锁屏使用透明的系统活动背景着色和语义色文字，灵动岛展开态显示完整信息卡，收起态只显示图标和端口，不绘制自定义背景。锁屏实时活动和灵动岛展开态提供“停止 HTTP API”按钮：运行中的主脚本关闭端口、结束实时活动并释放保活，然后保留脚本界面；若主脚本已退出，Intent 只清理残留活动并阻止下次自动重启。也可在概览或“更多”页关闭服务。收起界面后脚本实例继续运行；恢复脚本时会重新检查保活。关闭 HTTP 服务或正常退出脚本会释放保活并请求立即移除实时活动；若系统返回结束失败，“更多”页会显示错误，并在下次运行时重试。若系统未允许实时活动或后台保活，服务仍可在前台使用，“更多”页会显示状态。iOS 仍可能因系统策略、锁屏或资源限制挂起或终止脚本，实时活动的显示也不代表接口一定可达。局域网监听使用明文 HTTP 且无鉴权，同一网络内的设备都可以调用，请仅在可信网络中开启。
