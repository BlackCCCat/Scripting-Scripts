# WorkBuddy2API for Scripting

在 iPhone 的 Scripting 中直接授权 WorkBuddy / CodeBuddy 账号，查看余额、签到和成长任务，并提供本机或局域网 OpenAI 兼容 HTTP 接口。无需另行部署面板。

首次运行会显示 [更新说明](changelog.md)；阅读后不再重复弹出，文档内容更新时会再次显示。

## 使用

1. 在“账号”页添加账号，选择站点后点“登录授权”，脚本会获取授权链接并直接在 Scripting 内的 Safari 视图打开。也可以点“从钥匙串导入”，每次手动选择一条；只接收包含 UID、Access Token 和明确 WorkBuddy 标识或域名的凭据 JSON，其他记录会跳过。替换已有账号时会先确认。导入的凭据保存在本脚本的 Keychain 中，键名包含 UID 和昵称，便于其他脚本辨认；启动时会迁移当前脚本可访问的旧键名，清理失败会提示。没有刷新令牌的凭据到期后需要重新授权或再次导入。账号列表左滑可停用或启用账号；停用仅影响 HTTP API 账号轮询和模型列表，账号详情与任务操作仍可使用。
2. 在“任务”页点底部“一键执行任务”：脚本重新读取全部账号任务，依次补领已达标奖励，推进当前支持的 `first_buddy`、`chat_5`、`Model_chat_GLM5.2`，回读进度后再补领新达标奖励。每项会记录已处理、待上游确认、失败或跳过；有可执行任务且执行前后积分查询都成功时，本轮结果会显示积分变化。当前没有自动推进动作、未解锁、国际区只读的任务直接跳过。GLM-5.2 对话会发起真实模型请求，可能消耗账号额度；首只 Buddy 会同意上游领养协议。任务页自动加载并按账号显示任务状态，未领取任务按国内、国际分组；账号详情仍可单独接受或领取任务。国内任务合并桌面、小程序和等级三种列表来源，优先保留可领奖任务；单一来源请求失败会提示，并继续显示其他来源。任务页及账号详情只显示待处理任务，以及有可靠日期为当天的已领取任务；本机领取会记录领取时间。上游任务列表没有提供完成时间的历史已领任务不会显示。
3. 在“概览”顶部卡片右下角或“更多”页启动服务。默认只监听本机并固定使用端口 `8787`；可以在“更多”页编辑地址和端口，保存后运行中的服务会按新端口重启。自定义地址用于复制连接地址，监听范围由局域网开关控制；端口被占用时会报错，不会自动改用随机端口。
4. API 客户端的 Base URL 使用“更多”页复制的地址并加 `/v1`；接口不校验鉴权头，API Key 可任意填写或留空。局域网设备改用页面显示的手机 IP。

“概览”展示账号状态、余额、本机 API 请求观测到的模型限流和最近 24 小时每小时的本机用量；图表可左右滑动，默认显示最近 10 小时。启动或从最小化恢复时会自动刷新余额。国内个人账号的今日签到状态在当天首次运行时从上游查询，之后沿用本机保存的结果；账号增删或点击签到后会重新查询，查询失败会在下次运行重试。点击顶部卡片的账号区域或左下角签到状态可为未签到账号签到；左下角蓝点表示已签到、绿点表示待签到、红点表示其他状态，右下角开关控制 HTTP API 服务，右上角可手动刷新余额。模型锁池只显示尚未解除的模型级限流，未观测到的上游限流不会出现在这里；上游未给出重置时间时显示本机重试时间。“数据”统计本机保留的请求记录，启动或恢复时自动重新读取，可按今天、最近 3/7/30 天或总计，以及账号、模型、区域查看最近 200 次请求。积分消耗与缓存命中只在上游响应含对应字段时显示。“更多”可查看本机请求日志、查询并领取账号礼包，以及查看开学季活动留下的券码。补偿活动已被上游移除，页面只保留状态说明。

```sh
curl http://127.0.0.1:8787/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"cn:glm-5.2","messages":[{"role":"user","content":"你好"}],"stream":false}'
```

`GET /v1/models` 列出“更多 → 模型”中启用、且至少有一个未停用账号提供的模型；关闭账号轮询后只列出所选固定账号的模型。模型目录从上游账号自动拉取（`/v3/config` 与企业端点并集，过滤非对话模型和 auto/fast-model/balanced-model 路由项）；旧目录在首次打开模型页或请求 `/v1/models` 时自动刷新。国内账号的模型以 `cn:` 前缀、`owned_by: "Workbuddy"` 提供；国际与旧国际账号的模型以 `global:` 前缀、`owned_by: "Workbuddy AI"` 提供。客户端使用返回的完整模型 ID 请求聊天，前缀不会传给上游；目录已记录的模型只路由到实际返回该模型的账号。模型开关只控制列表展示，不验证账号的实时使用权限。`stream: true` 使用逐块 HTTP 响应转发上游 SSE，`stream: false` 返回完整 JSON；可用 `curl -N` 检查增量输出。DeepSeek 模型默认发送 `thinking: {"type":"enabled"}` 与 `reasoning_effort: "high"`；客户端可指定档位，或以 `thinking.type: "disabled"`、`reasoning_effort: "off"` 关闭推理。推理内容在流式事件的 `delta.reasoning_content` 或非流式消息的 `reasoning_content` 中返回。上游模型、计费及任务接口可能变化，应以实际账号联调结果为准。

聊天接口默认按请求模型在可用账号间轮流分配新会话；同一会话在 30 分钟内优先复用首次成功的账号，以提高缓存命中。客户端可用 `conversation_id`、`metadata.conversation_id` 或 `prompt_cache_key` 明确标识会话；未提供时，脚本根据首条用户消息推断，同样的开场内容可能被当作同一会话。已知余额为零的账号会被跳过；明确额度耗尽或模型限流时会尝试其他账号。流式响应开始发送后无法换号重试，后续上游错误会作为 SSE 错误事件返回。普通 429 按短时冷却处理；余额刷新显示恢复后，额度耗尽账号可重新参与。可在“更多 → 本机 API 服务”关闭账号轮询并选择固定账号；固定账号停用、额度耗尽、模型受限或请求失败时直接返回错误。账号绑定和轮询位置仅保存在当前脚本实例中。

聊天上游请求超时为 600 秒；本机 HTTP 连接在收全请求前使用 60 秒空闲超时，进入生成阶段后为 610 秒；流式响应每 15 秒发送一次 SSE 心跳，以降低长时间思考时的空闲断线概率。客户端断开时立即取消上游请求；非流式请求同样如此。非流式请求在生成结束前无法发送内容，客户端自身的超时及 iOS 后台网络中断仍可能导致“网络连接已中断”。

“更多 → 请求诊断日志”默认开启。每次启动 HTTP 服务都会替换上一轮诊断日志；关闭服务后可逐条查看请求，或点“查看日志”滚动浏览完整文本，也可清理、导出按设备当前时区排列的 `.log` 文件。列表显示结果、耗时和失败摘要；详情记录脱敏账号、换号决定、上游连接、流式思考与回答的开始时间和字符数、思考持续时间、等待上游数据的间隔、响应字节数、流式心跳及客户端断开位置。非流式请求要等上游完整返回，期间只有连接和读取阶段，无法得知逐段思考进度。日志保留状态码和上游业务码，但不保存请求正文、思考文字、访问令牌或完整上游错误体；未知错误原文会省略，无法仅凭日志判断上游内部原因。页面为保持流畅只展示本轮最近 200 条请求，每条最多 80 个阶段事件；设备日志文件保留本次运行全部已记录事件，下次启动服务时覆盖。导出时通过系统分享面板交付文件，分享前请确认接收方。

Scripting 的 HTTP 服务仅在脚本实例存活时工作，使用 Node 兼容层的 TCP 监听处理 HTTP/1.1；当前运行时最多接受 32 个原生连接。启动服务后会请求 `BackgroundKeeper` 后台音频保活，并显示锁屏实时活动；支持灵动岛的 iPhone 会显示服务图标和端口，展开后可查看访问范围与保活状态。实时活动沿用 WLOC 的原生布局方式：锁屏使用透明的系统活动背景着色和语义色文字，灵动岛展开态显示完整信息卡，收起态只显示图标和端口，不绘制自定义背景。锁屏实时活动和灵动岛展开态提供“停止 HTTP API”按钮：Intent 先请求立即移除实时活动；主脚本收到该活动的结束事件后关闭 HTTP 端口、释放保活并退出。若主脚本当时无法执行，停止标记会阻止下次运行自动重启服务。也可在概览或“更多”页关闭服务，这两个入口只停服务并保留界面。收起界面后脚本实例继续运行；恢复脚本时会重新检查保活与活动停止状态。关闭 HTTP 服务或正常退出脚本会释放保活并请求立即移除实时活动；若系统返回结束失败，“更多”页会显示错误，并在下次运行时重试。若系统未允许实时活动或后台保活，服务仍可在前台使用，“更多”页会显示状态。iOS 仍可能因系统策略、锁屏或资源限制挂起或终止脚本，实时活动的显示也不代表接口一定可达。局域网监听使用明文 HTTP 且无鉴权，同一网络内的设备都可以调用，请仅在可信网络中开启。
